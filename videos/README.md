## 三条规矩

- **按路线走**：每条视频都属于一条已定路线，路线外的题材先提新路线。见 [process/ROUTES.md](../process/ROUTES.md)。

- **剧本闸门（不可逾越）**：视频的所有文字由项目负责人逐条审核、和 AI 讨论打磨，负责人明确说"确认剧本完善"后，
  才能配音、渲染。确认记录写在项目 `SCRIPT.md` 开头；没有这一行，`vlab-tts` 和 `vlab-build` 拒绝执行。
  流程见 [process/SCRIPT-REVIEW.md](../process/SCRIPT-REVIEW.md)。
- **输入和成片都入库**：配音和配乐 wav、时间轴、字幕、分镜片段入库，正在做的片子的成片也入库；归档以后成片不再入库（见 [process/REPO.md](../process/REPO.md)）。

## 目录结构

一个 `project.yaml` 描述全片：每个镜头用哪个渲染器（manim、remotion、glsl、custom）、哪张卡、传什么参数。
`SCRIPT.md` 是剧本和审核记录，`content/` 是配音稿，`build/` 是配音、时间轴、字幕，`media/clips/` 是分镜片段，
`renders/` 是成片（入库）。重建、增量缓存、体检都走 `toolkit/vlab` 的工具。

不放这里：试验和调研放 `research/`，公共代码放 `toolkit/vlab/`。视频只依赖 `toolkit/vlab/`。

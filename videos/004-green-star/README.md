## 讲了什么

夜空里有红星、蓝星、白星，唯独没有绿星。按"温度决定颜色"的直觉，从最热的蓝到最冷的红，
中间是白、黄、橙，就是没有绿。

可是倒着算一下：峰值落在绿色需要 5100–5800 度，而太阳是 5772 度，正好在区间里。
太阳本该是一颗绿色的恒星，但它看起来一点也不绿。

问题出在一个错误的假设：发光最强的颜色，就是我们看到的颜色。恒星在整个可见光范围里都在发光，
太阳在蓝、绿、红三段的强度是 **0.99 : 1.00 : 0.88**，几乎一样多，混在一起就是白色。

**结论**：不是绿色缺席了，是只要绿色最强，红和蓝就一定也很强。这个问题本身问错了。

## 这条片踩到的坑

| 坑 | 怎么回事 | 怎么解决 |
|---|---|---|
| 两个着色器串画面 | s11、s21、s25 渲染出来全是大气散射的山和地平线 | `glsl.py` 原来每个渲染器建一个 OpenGL 上下文，同线程交错渲染会互相覆盖。改成全进程共用一个上下文 |
| 成片比剧本短一大截 | 剧本按"画面时长"估 3 分 18 秒，实际配音只有 2 分 06 秒 | 成片长度由旁白字数定，中文约 0.236 秒/字。补内容到 898 字，而不是拉长留白 |
| 绑定的词不存在 | "一颗"被 Edge TTS 切成 一/颗，"蓝白"切成 蓝/白色 | 写画面脚本前先把整段词表打出来看一遍 |
| 色块出现前留黑块 | `VGroup.arrange` 后未淡入的块已占位 | 先 `set_opacity(0)`，淡入时才显形 |
| 星空有方块状亮斑 | 格子化星场只算当前格，星星光晕在格子边界被硬切 | 扫 3×3 邻格，并让光晕在一格内衰减干净 |
| 收尾句压在色带上 | Closing 段坐标轴和文字位置冲突 | 坐标轴上移，文字下移到色带下方 |
| O 型和 B 型色块颜色相同，"黄白""黄"都显白 | 色温函数把温度截断在 15000K，35000K 和 15000K 算出来一样；白点 6500K 让 6800K 以上全是白 | 上限提到 40000K；色块按天文学惯例以 A 型为白点，再加饱和拉开色阶 |
| M 块看着和 K 块一样是橙 | 黑体色相从 4200K 到 2400K 几乎不变（约 32°），只差饱和度；"红"是惯例叫法，物理上算不出 | M 块单独把色相推到 15°（红橙），其余六块保持纯黑体色 |
| 第二段的结论一闪而过 | 缺口、"绿？"、结论标题三样都挤在旁白"没有"之后，结论完整显示只有 0.6 秒就切镜 | 缺口和"绿？"提前到"这一整串颜色里"出，结论跟着"没有"出，停留约 1.5 秒 |
| 换字体后烧字幕可能悄悄退回雅黑 | libass 找不到思源黑体时先退到 Arial、再退到微软雅黑，画面看着正常 | `vlab-finalize` 传仓库字体目录 `fontsdir`，实测选中思源黑体 |

## 事实与简化

所有数字的来源见 [content/facts.md](content/facts.md)，物理数字可以用 `uv run python content/verify.py` 自己算一遍。

画面上标注了的简化：
- 参宿四写"约 3600 度（估计值）"，各来源从 2500 到 3900 度都有；
- 光谱型温度边界标了"各来源略有差异"；
- 三段强度标了"450 / 550 / 650 纳米处的相对强度，由普朗克定律算出"。
- 光谱型色块按天文学惯例着色，以 A 型为白，所以 F 型显黄白、G 型显黄。M 型的色相单独推到红橙（15°）：黑体在恒星温度下算不出红，色相一直停在橙（约 32°，和 K 型同色相，只差饱和度），而"红巨星"的"红"本来就是惯例叫法。太阳特写的着色器白点约 6500K，太阳在大气外看就是白的。两者的差距正是 s19–s21 讲的内容，色块下方的小字已注明。

普朗克曲线在可见光范围内看着很平（0.79–1.00），这不是画错了，正是这一段要讲的：
整个可见光范围都差不多强。画面上用一行小字点明"纵轴从 0 开始"，没有为了好看截断纵轴。

# process：流程

**类别：流程。** 我们怎么做一条视频：每一步做什么、要过哪道关、谁拍板。
这里的规则由项目负责人定，AI 必须遵守，不能自行改动。

和 `docs/` 的区别：`docs/` 是参考资料（技术路线、视频类型、设计文档、进度）；这里是必须遵守的流程和规则。

## 一条视频的流程

| 步骤 | 做什么 | 这一关的规则 | 谁拍板 |
|---|---|---|---|
| 1 选题 | 定题目、落点、对标 | [ROUTES.md](ROUTES.md)：题目必须属于已定路线，路线外的先提新路线；[STYLE-IMPACT.md](STYLE-IMPACT.md)：五条硬规矩，传播优先但不牺牲质量 | 项目负责人 |
| 2 剧本 | 所有文字写进项目的 `SCRIPT.md`，事实标来源 | [SCRIPT-REVIEW.md](SCRIPT-REVIEW.md)：剧本闸门，不可逾越 | 项目负责人逐条审核，明确说"确认剧本完善" |
| 3 制作 | 配音、渲染镜头、拼接、混音 | 剧本没确认，`vlab-tts` 和 `vlab-build` 拒绝执行；做法约定见根目录 `AGENTS.md`「工作约定」 | AI 执行 |
| 4 体检 | 节奏、逐帧、响度，逐项核对画面内容和标签 | [STYLE-RHYTHM.md](STYLE-RHYTHM.md)：硬指标为观感服务 | AI 自检 |
| 5 发布 | 标题、封面、字幕、平台声明 | [PUBLISH.md](PUBLISH.md)：发布前检查清单 | 项目负责人 |
| 贯穿 | 入库、提交、推送 | [REPO.md](REPO.md)：什么进 git；没有负责人明确指令不提交、不推送 | 项目负责人 |

## 规则文件

| 文件 | 管什么 | 定下的日期 |
|---|---|---|
| [ROUTES.md](ROUTES.md) | 内容路线：现在做哪几条线、哪些题材不做、开新路线的流程 | 2026-10-26 |
| [SCRIPT-REVIEW.md](SCRIPT-REVIEW.md) | 剧本审核：视频的所有文字由项目负责人逐条审核、明确确认后才能往下做 | 2026-10-26 |
| [STYLE-IMPACT.md](STYLE-IMPACT.md) | 传播与共鸣规范：对标比特新语的五条硬规矩；传播决定怎么讲，质量是底线 | 2026-10-25，2026-10-26 补"不牺牲质量" |
| [STYLE-RHYTHM.md](STYLE-RHYTHM.md) | 节奏与质检硬指标：片长、镜头密度、特效边界、`vlab-review` 的判定依据 | 2026-10-25 |
| [PUBLISH.md](PUBLISH.md) | 发布流程与检查清单：AI 声明、配乐、字体、题材红线 | 2026-10-23，2026-10-26 移到这里 |
| [REPO.md](REPO.md) | 入库与提交：什么进 git、成片怎么处理、提交和推送的规矩 | 2026-10-26 |

## 改规则

- 规则只由项目负责人定或改。AI 可以提建议，不能自行改动；改动要写明日期和原因。
- 硬规矩在根目录 `AGENTS.md` 开头有摘要，AI 每次对话都会读到；细则以这里为准。

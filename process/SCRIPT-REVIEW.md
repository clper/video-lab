# 剧本审核流程（剧本闸门）

**2026-10-26 项目负责人定，不可逾越。**
视频的所有文字内容，都必须由项目负责人逐条审核，和 AI 讨论、打磨完善；
负责人明确说"确认剧本完善"之后，才能进入下一步（配音、渲染）。剧本质量差，后面画面做得再好也救不回来。

---

## 1. "所有文字"包括什么

一个字都不漏，凡是观众会看到或听到的都算：

| 类别 | 例子 |
|---|---|
| 标题 | 视频标题、备选标题、封面上的字 |
| 旁白 | 配音稿的每一句（content/*.json 的 narration） |
| 字幕 | 烧进画面的字幕；拍格模式下每镜的 text |
| 画面文字 | 镜头卡和模板里的每一行字：大标题、小字注释、章节名、数据标注、图例、更正说明、片尾 |
| 数据和事实 | 画面和旁白里出现的每个数字、人名、年份、引文（来源记在项目的 facts 表里） |

## 2. 流程

1. **AI 起草**：`SCRIPT.md` 开头写明这条视频属于哪条路线（见 [ROUTES.md](ROUTES.md)），
   再把全部文字集中写进去，按镜号逐条列出旁白、字幕、画面文字，
   每个事实和数字标明来源。负责人只看这一个文件，就能看到片子里的全部文字。
2. **负责人逐条审核**：指出问题，和 AI 讨论。
3. **AI 修改**：按讨论结果改，在 `SCRIPT.md` 的修订记录里写清这一轮改了什么、为什么。
4. 第 2、3 步反复进行，直到负责人满意。
5. **负责人明确确认**：负责人说"确认剧本完善"（或同样明确的确认），AI 才在 `SCRIPT.md` 开头记一行：

   ```
   剧本确认：已确认 2026-10-27（项目负责人原话：「确认剧本完善」）
   ```

6. **之后才能进入下一步**：配音、生成时间轴、渲染、合成。

确认之前，`SCRIPT.md` 开头写的是：

```
剧本确认：待审
```

## 3. 硬规矩

- **AI 不得自行判定剧本已完成**，不得替负责人写"已确认"。"差不多了""应该可以了""先这样"都不算确认。
- **确认之前不做下一步**：不配音、不生成时间轴、不渲染正式镜头、不合成。
  工具会拦：`videos/` 下的正式项目，`SCRIPT.md` 里没有"已确认"这一行，`vlab-tts` 和 `vlab-build` 直接拒绝执行
  （`vlab-build --check` 只做校验，不受限）。实现在 `toolkit/vlab/tools/script_gate.py`。
- **确认之后又改了任何文字，确认作废**：哪怕只改一个字，AI 都要把那一行改回"剧本确认：待审"，
  写明改了什么，重新请负责人审核。确认只对当时那一版有效，不延伸到之后的修改。
- **想先看画面效果，去 research/ 做**：试风格、试镜头卡的样片放在 `research/` 下，不进正式项目，
  也不用正式剧本的文字冒充定稿。
- `research/` 和 `archive/` 下的项目不受这个闸门限制（试验和存档）。

## 4. 和其他规范的关系

- `process/STYLE-IMPACT.md` 决定"讲什么、怎么讲才有人看"，`research/content/README.md` 的 06 节写怎么核实事实；
  它们都是审核时的参考，**最后拍板的是项目负责人**。
- 传播优先，但不牺牲质量：可以为传播删减和简化，不能说错，简化的地方在画面上标注。
  标题和画面文字同样适用，不允许"标题先说过头、片尾再更正"。

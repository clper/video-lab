# 入库与提交

**2026-10-26 项目负责人定。** 目标：克隆下来就能快速用，每条成片都能完美重生成。
**2026-10-28 项目负责人定：** 能用代码重出的分镜片段不入库（仓库打包已到 414 MB，每条片子入库上百 MB）。

## 什么进 git

| 内容 | 入库吗 | 为什么 |
|---|---|---|
| 源码、稿子、剧本、时间轴、字幕 | 入库 | |
| 配音和配乐 wav（各项目 `build/`） | 入库 | 重跑配音时间轴会变，画面要全部重做，所以配音不能当成可重建的东西 |
| 分镜片段（`media/clips/`、`media/videos/`） | 入库，例外见下一行 | 有了它们，成片只要 ffmpeg 拼接；着色器片段要显卡才能重渲 |
| `videos/`、`research/` 里能用代码重出的分镜片段（remotion、manim、custom 渲染的） | 不入库（2026-10-28） | 缺了 `vlab-build` 按镜头指纹自动重渲（要 Node 和 Remotion 依赖）；remotion 重渲和原片段肉眼一致，逐像素有不到 1/255 的渲染噪声。镜头指纹 `.hash` 照常入库，克隆后重渲完片段，入库的成片不会被重新拼一遍。着色器片段仍入库，新的用 `git add -f` 加；`archive/` 是冻结的快照，不受这条影响 |
| `videos/` 下正在做的正式视频的成片 | 入库 | 克隆后能直接看到正在做的片子 |
| `archive/` 和 `research/` 的成片 | 不入库 | 从入库的输入一条命令重新生成，实测和原片逐帧一致（见 `archive/README.md`） |
| 合并其他来源时的临时副本目录 | 不入库，合并完就删 | 「其他AI推进」已在 2026-10-28 删除 |
| 环境、工具缓存碎片、用完即删的过渡文件 | 不入库 | 一条命令能重建 |
| 密钥、模型权重 | 不入库 | 密钥只放本地 `.env`；权重按实验 README 下载 |

规则的实现在 `.gitignore`，开头有原则说明。新增一类产物时，先按这张表判断，再改 `.gitignore`。

**已经入库的片段还在历史里**：取消跟踪只让以后不再变大，已有的 414 MB 不会变小。要变小得改写 git 历史并强制推送，
会影响所有已有的克隆，要项目负责人另外明确同意才做。

**片子归档时**：从 `videos/` 移到 `archive/` 后，它的成片就不该再入库。`.gitignore` 会挡住新文件，
但已经跟踪的成片要提交前手动取消跟踪：`git rm --cached <成片路径>`，文件留在本地。

## 提交和推送

- 没有项目负责人在当次对话里明确说"提交"或"推送"，AI 不做 `git commit`，也不做 `git push`。
- 一次指令只针对当次改动，不延伸到后续任务；每一轮新改动都要重新获得指令。
- 改完先停在工作区，列出改动文件清单，等负责人的指令。

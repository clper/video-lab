# 视频类型纲要：画面风格 × 内容形态

选题和设计分镜时查这份：先定内容形态，再按第三节挑画面风格的组合。
技术细节（环境、门槛、AI 可写程度）见 `TECHNOLOGY.md`。

**做法层级**（第四节详细说明）：

- **纯代码**：画面完全由代码生成，AI 能全程完成，可复现、改起来便宜。
- **代码 + 素材**：代码负责动画、版式、合成，画面的一部分来自现成素材（图片、录屏、实拍、模型）。
- **代码 + 工具**：需要专门软件（Blender、骨骼动画工具等），代码通过脚本驱动它们。

不做：黏土 / 定格动画、写实人物 / 动物 / 实拍画面。

## 一、画面风格：可做纲要

| 画面风格 | 典型效果 | 做法层级 | 用什么做 | 状态 |
|---|---|---|---|---|
| 数学 / 几何动画 | 公式推导、图形连续变形 | 纯代码 | Manim | ✅ 已验证（001、002） |
| 信息图 / MG 动画 | 图标、数据卡、标题动效 | 纯代码 | HyperFrames、videokit 模板、Pillow | ✅ 已验证（000、research/visual/08） |
| 数据可视化 | 柱状图、排行、地图、走势 | 纯代码 | HyperFrames、Manim、videokit 模板 | ✅ 部分验证（research/visual/08 对比柱） |
| 文字动效 | 歌词、金句、逐词跳字 | 纯代码 | HyperFrames、Remotion | 能做，未验证 |
| 像素风 / 复古游戏 | 像素小人、RPG 对话框、芯片音乐 | 纯代码 | Python 精灵图 + 有序抖动 | ✅ 已验证（research/visual/11） |
| 扁平插画 / 剪影 | 分层视差风景、逆光剪影动物 | 纯代码 | Python 程序化 2.5D | ✅ 已验证（research/visual/06） |
| 写实氛围空镜 | 云海、天空、雪山、日落、星空 | 纯代码 | GLSL 着色器 | ✅ 已验证（research/visual/07、003） |
| 抽象 / 生成艺术 | 粒子、流场、分形、光效 | 纯代码 | Python、p5.js、着色器 | ✅ 已验证（research/visual/05、research/visual/10） |
| 低多边形 3D | 折纸感的山川、动物、小场景 | 纯代码（也可用 Blender） | Three.js、着色器 | 能做，未验证 |
| 等距视角 | 小城市、工厂流程、系统架构 | 纯代码 | 2D 绘制、Three.js | 能做，未验证 |
| 科学模拟 | 流体、沙子、天体、物理实验 | 纯代码 | Taichi、Manim | 能做，未验证 |
| 赛博 / 故障风 | 霓虹、扫描线、画面撕裂 | 纯代码 | 着色器、FFmpeg 特效 | 部分验证（research/visual/02） |
| 拼贴 / 剪纸风 | 照片剪贴、纸片翻动 | 代码 + 素材 | 代码做动画；图片素材（可 AI 生成）+ 自动抠图 | 能做，未验证 |
| 手绘 / 水彩 / 素描风 | 水彩晕染、铅笔线条 | 代码 + 素材 | 着色器风格化滤镜作用在插画或图片上 | 能做，未验证 |
| 实拍素材包装 | 口播字幕、B-roll、贴纸叠加 | 代码 + 素材 | FFmpeg、HyperFrames；画面来自拍摄或录屏 | 能做，未验证 |
| 卡通角色动画 | 表情丰富、动作流畅的二维角色 | 代码 + 工具 | 简单角色纯代码（矢量骨骼）；复杂表演用 Spine / Live2D 绑骨骼 | 简单版能做，未验证 |
| 写实 3D 产品 / 建筑 | 产品广告、室内漫游 | 代码 + 工具 | Blender 脚本驱动 + 模型材质素材 | 基础验证（research/visual/04，原开发机） |

规律：能用规则、几何、数学、固定帧描述的画面，代码擅长；依赖海量真实细节的（人脸、毛发、真实表演）交给素材或工具。

## 二、内容形态

| 内容形态 | 典型例子 | 核心诉求 | 常见时长 | 代码适配 |
|---|---|---|---|---|
| 知识科普 | 天为什么是蓝的、浮点数精度 | 讲清原理、有记忆点 | 45–90 秒 | ✅ 最适合（001–003） |
| 数据播报 | 排行、趋势、财报解读 | 数字准确、变化直观 | 30–60 秒 | ✅ 适合，可模板化量产 |
| 资讯快讯 | 热点新闻、行业动态 | 快、批量、版式统一 | 15–45 秒 | ✅ 适合模板化 |
| 故事短片 | 绘本、童话、寓言 | 角色可爱、情绪起伏 | 30–120 秒 | ✅ 像素 / 插画风可做（research/visual/11） |
| 历史 / 人物传记 | 一段历史、科学家生平 | 时代感、叙事 | 1–3 分钟 | 🟡 叙事可做，需要历史图片、肖像素材 |
| 产品 / 品牌宣传 | 产品发布、功能介绍 | 质感、卖点清楚 | 15–60 秒 | 🟡 MG 部分纯代码，产品外观需要 3D 模型或实拍 |
| 教程演示 | 软件操作、步骤讲解 | 步骤清晰可跟做 | 1–5 分钟 | 🟡 需要录屏素材，标注和包装用代码 |
| 观点评论 / 口播 | 个人观点、点评 | 人设、信任感 | 1–3 分钟 | 🟡 主画面是真人出镜，代码做包装 |
| 音乐视频 | 歌词 MV、音乐可视化 | 卡点、情绪 | 1–4 分钟 | ✅ 文字动效、生成艺术卡点 |
| 金句 / 情绪短片 | 语录、治愈系 | 氛围、共鸣 | 10–30 秒 | ✅ 适合 |
| 氛围长视频 | 助眠、学习陪伴、白噪音 | 循环、耐看 | 30 分钟到数小时 | ✅ 极适合（程序化画面可无限循环、零成本） |
| 片头片尾 / 转场 | 栏目 Logo 演绎 | 辨识度 | 3–10 秒 | ✅ 适合 |

## 三、内容 × 风格：推荐组合

一条好视频通常是几种风格的组合：**主风格**负责讲清楚，**辅风格**负责好看和情绪，**点缀**负责钩子和转场。
组合时守一条规矩：**全片统一色板和字体**，风格再多也像一条片子（003 就是这么做的）。

| 内容形态 | 主风格（讲清楚） | 辅风格（好看、情绪） | 点缀（钩子、转场） | 典型结构 |
|---|---|---|---|---|
| 知识科普 | 数学几何、信息图 | 写实氛围空镜、扁平插画 | 科学模拟、生成艺术 | 空镜提问 → 原理动画 → 数据对比 → 回到空镜收尾（003） |
| 数据播报 | 数据可视化 | 信息图 | 文字动效、等距视角 | 数字冲击开场 → 图表变化 → 结论卡 |
| 资讯快讯 | 信息图 | 文字动效 | 拼贴（新闻配图） | 标题 → 三个要点卡 → 结尾 |
| 故事短片 | 像素风或扁平插画（二选一定基调） | 写实氛围空镜做天空背景（统一调色） | 生成艺术做魔法、光效 | 建立场景 → 起冲突 → 高潮 → 收尾（research/visual/11） |
| 历史 / 人物 | 拼贴剪纸（历史图片）+ 扁平插画 | 等距视角（地图、城市） | 手绘素描滤镜做旧 | 时代背景 → 人物经历时间线 → 影响 |
| 产品宣传 | 信息图 / MG | 写实 3D 产品 | 文字动效、赛博风 | 痛点 → 产品亮相 → 功能逐条 → 行动号召 |
| 教程演示 | 实拍素材包装（录屏） | 信息图 | 等距视角（流程图） | 目标 → 分步骤（录屏 + 标注）→ 小结卡 |
| 观点评论 | 实拍素材包装（口播） | 信息图、数据可视化（论据） | 拼贴 | 观点 → 论据配图表 → 结论 |
| 音乐视频 | 文字动效 | 生成艺术、赛博故障风 | 像素风 / 插画（副歌换景） | 按节拍分段，副歌加强视觉 |
| 金句情绪 | 写实氛围空镜或扁平插画 | 文字动效 | 手绘水彩滤镜 | 空镜 + 一句话慢慢出现 |
| 氛围长视频 | 写实氛围空镜或像素风场景 | 生成艺术（雨、雪、萤火虫） | — | 一个场景循环 + 细微变化（日夜、天气） |
| 片头转场 | 生成艺术、赛博故障、写实空镜 | 文字动效 | — | 3–5 秒 Logo 演绎 |

## 四、三种做法层级

### 难度是否依次增加

对"让 AI 写代码做视频"来说，是依次变难，但难在不同地方：

| 层级 | 难在哪 | AI 能做多少 |
|---|---|---|
| 纯代码 | 难在"写"：图形学、调参；写好以后完全可复现 | 全程 |
| 代码 + 素材 | 难在"素材"：获取、风格统一、角色前后一致、版权；代码部分反而简单 | 代码全程；素材要生成或挑选 |
| 代码 + 工具 | 难在"工具"：安装、学习曲线、渲染慢、很多操作在图形界面里 | 只能写其中的脚本部分 |

### 素材指什么；AI 画的图行不行

素材包括：图片（照片、插画、图标、纹理、Logo）、视频（实拍、录屏、B-roll）、音频（音乐、音效）、3D 模型、字体。

**AI 生成的图片可以用，而且是性价比很高的组合**：AI 画静态图，代码让它动起来、排版、配音对齐。

- **一张图**：当背景或插图。代码做推拉摇移运镜；自动抠图把它拆成前中后景做视差（2.5D）；
  加局部动效（云飘、水波、光斑）和文字。一张静图能变成几秒有纵深的镜头。
- **很多张图**：做绘本、历史、拼贴类故事。难点是**一致性**：同一个角色在每张图里要长得一样，整体画风要统一。办法：
  - 先出一张角色设定图，固定提示词和参考图，每张都拿它做参考；
  - 或者让 AI 只画背景和道具，角色用代码画（像素或矢量），角色一致性由代码保证。
- **注意**：
  - 竖屏要够大（1080×1920），不够就放大；
  - AI 图里的文字经常写错，文字一律用代码叠加；
  - 版权和平台条款要看所用模型的说明；
  - 这会放开 TODO 里"排除大模型"的规则（只用于静态图素材，不用于生成视频），要不要放开由项目负责人决定；
  - 本机 GTX 1060 6GB 能本地跑轻量的图像模型但很慢，调用在线接口更省事。

### 工具不只是 Blender

| 工具 | 解决什么 | 代码怎么接 | 接入难度 |
|---|---|---|---|
| 抠图 / 分割模型（如 rembg） | 把一张图拆成前景、背景层 | Python 库，直接调用 | 低（几乎等于代码） |
| 语音识别（如 Whisper） | 口播视频自动出字幕、剪掉语气词 | Python 库 | 低 |
| Blender | 3D：写实、产品、低多边形、带骨骼的角色模型 | Python（bpy）+ 命令行后台渲染 | 中 |
| Spine / DragonBones / Live2D | 2D 骨骼角色：表情、口型、走路 | 绑骨骼在界面里做；动画播放、口型对齐由代码驱动 | 中高 |
| Unreal / Unity | 电影级实时 3D | Python / C# 脚本，但主要靠编辑器 | 高 |
| After Effects | 专业动效 | 脚本能力有限，主要人工 | 高，不作为主路线 |

优先顺序：AI 类工具（抠图、识别）最好接，几乎和代码一样；Blender 其次（全程可脚本化）；骨骼动画和游戏引擎最后。

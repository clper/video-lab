# audio：音频研究

**定位**：声音是视频的另一半。这里研究配音、混音、音乐、音效、音画同步，
目标是让每条视频"听起来专业"，并且和代码生成的画面一样：可复现、可自动化、改一处重出一版。

和其他目录的分工：`research/visual/` 研究画面技术；`research/audio/` 研究声音；`research/frontier/` 研究前沿生成模型（其中音视频联合生成两边都会涉及，结论互相引用）。

## 现状：仓库里已有的音频能力

| 能力 | 在哪 | 说明 |
|---|---|---|
| 配音 + 词级时间轴 | `toolkit/vlab/pipeline/tts.py`（命令 `vlab-tts`） | Edge TTS，免费、在线；每个词的时间点驱动画面出场 |
| 字幕 | `vlab-tts` 生成 ASS / SRT | research/visual/11 还做了 RPG 对话框，按词级时间点逐字打出 |
| 混音规范 + 自动避让 | `toolkit/vlab/audio/mix.py` | 说话时配乐稳定压低 8 dB，停顿时 0.5 秒内回来；成片立体声 -14 LUFS、真峰值 -1.5 dBTP，响度两遍标准化（见 02） |
| 事件驱动音效 | `toolkit/vlab/audio/sfx.py` | 12 种代码合成音效；画面事件清单 → 音效轨，零手工对位（见 09） |
| 程序化配乐 | `toolkit/vlab/audio/music.py` | 一种：小调四和弦铺底 + 琶音 + 轻鼓；research/visual/11 另有芯片音乐 |
| 实际用例 | `research/visual/12-kinetic-type` | 配音 + 71 个事件音效 + 自动避让配乐，一次合成 |

已知短板：配音只有 Edge TTS 的固定音色，重音、停顿、情绪都控制不了；配乐只有一种风格；还没有声音标识（片头音）。

## 研究方向（编号 = 实验目录 `research/audio/NN-主题/`）

做法层级的含义见 `docs/VIDEO-TYPES.md` 第四节。

| 编号 | 方向 | 要回答的问题 | 做法 | 层级 | 状态 |
|---|---|---|---|---|---|
| 01 | 配音音色与语气 | 哪些音色适合哪类内容？语速、音调、停顿怎么配？ | Edge TTS 多音色对比；`rate` / `volume` / `pitch` 参数（不支持自定义 SSML） | 纯代码 | 待开始 |
| 02 | 混音规范与自动避让 | 配音、音乐、音效各多响？说话时音乐自动压低 | ffmpeg 侧链压缩 + 固定避让深度；两遍响度标准化 | 纯代码 | ✅ 第一版（2026-10-21） |
| 03 | 程序化背景音乐 | 能否按情绪、时长、节奏自动生成可用的配乐？ | 和弦进行 + 旋律生成 + 合成器音色（从 `vlab.audio.music` 扩展） | 纯代码 | 待开始 |
| 04 | 音效库 | 写实类音效（脚步、水、风）怎么获得？ | CC0 音效库（如 Kenney；Freesound 每个文件授权不同，需逐个确认） | 代码 + 素材 | 待开始 |
| 05 | 音画同步 | 画面卡音乐节拍、卡配音重音 | 节拍 / 起音检测（如 librosa，需 `uv add`）→ 时间轴 → 驱动画面 | 纯代码 | 待开始 |
| 06 | AI 配音 | 有没有比 Edge TTS 更自然、可控制重音和情绪的方案？ | 开源 / 商用 TTS 大模型对比（候选如 CosyVoice、F5-TTS、GPT-SoVITS，以调研时的最新版本为准） | 代码 + 工具 | 待开始 |
| 07 | AI 音乐与音效生成 | 用文字描述生成配乐、音效 | 开源模型（如 MusicGen、Stable Audio Open）和商用服务对比，重点看授权条款 | 代码 + 工具 | 待开始 |
| 08 | 口播素材处理 | 实拍口播的自动字幕、去语气词、降噪 | Whisper 语音识别 + ffmpeg 降噪 | 代码 + 工具 | 待开始 |
| 09 | 事件驱动音效 | 画面每个动作自动配上对应音效 | 代码合成音效 + 画面事件清单 → 音效轨 | 纯代码 | ✅ 第一版（2026-10-21） |
| 10 | 声音标识 | 两三秒的片头音，作为个人 IP 的"声音 Logo" | 代码合成旋律 + 音色设计，几个候选试听对比 | 纯代码 | 待开始 |
| 11 | 专属声音 | 固定一个独特音色，或克隆创作者本人的声音 | 依托 06 的模型；只克隆本人并经授权的声音；确认平台对合成声音的标注要求 | 代码 + 工具 | 待开始 |
| 12 | 多语言配音 | 同一套画面换一种语言重新配音（海外版） | 先配音后画面的流程天然支持：换语言重跑配音和渲染；研究词级绑定怎么跨语言 | 纯代码 | 待开始 |
| 13 | 氛围声景 | 雨声、篝火、森林等可无限循环的声音 | 程序化合成 + 无缝循环，配合"氛围长视频" | 纯代码 | 待开始 |

**建议顺序**：01 → 06 → 11（配音质感是最大的短板，三项连着做）→ 10（声音标识）→ 05（音画同步）→ 03（配乐扩展）→ 12 → 04 → 13 → 07 → 08。

## 规则

- **一个实验一个目录**：`research/audio/NN-主题/`，里面放脚本、`README.md`（问题、做法、结论、日期）和 `renders/`（试听样例，入库）。
- **试听样例统一按成片规范出**（立体声 -14 LUFS），横向比较才公平；每个样例旁边写清参数。
- **只依赖 `toolkit/vlab/`**，不依赖 `videos/`、`research/visual/`、`research/frontier/`。验证成熟、被视频复用的音频工具放进 `toolkit/vlab/audio/`。
- **素材必须记录来源和授权**：第三方音色、音乐、音效写明出处和授权方式；授权不明的不入库。
- 用到 API 密钥时只放在本地 `.env`（已在 `.gitignore` 里忽略），不写进代码。

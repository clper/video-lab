# frontier：视频生成前沿技术研究

**定位**：跟踪、讨论、试验前沿的视频生成技术，判断哪些值得接进我们的流水线、什么时候接、以什么方式接。

和 `research/visual/` 的区别：`research/visual/` 验证已经确定要用的技术，结论比较稳定；
`research/frontier/` 面向还在快速变化的技术，以调研和小规模试验为主，**所有结论都要带日期和来源**。

---

## 我们关心的核心问题

1. **代码管结构，模型管质感**：用我们的代码流水线（Manim、着色器、Blender、程序化场景）渲染出精确的结构信息
   （深度图、边缘图、分割图、相机轨迹），再交给视频生成模型补出写实质感。
   这样既保留代码的精确可控，又拿到代码做不出的真实细节。这是最值得投入的方向。
2. **补镜头**：代码做不了的少数镜头（写实动物、自然现象）用生成模型补，统一色调后混剪进代码生成的视频。
3. **一致性**：同一角色、同一画风在多个镜头里保持一致，这是生成模型目前最大的难点之一。
4. **成本和可复现**：生成模型按秒计费、要"抽卡"、结果难以复现；它和我们"改一行重出一版"的路线怎么共存。

## 研究方向（编号 = 以后的目录 `research/frontier/NN-主题/`）

| 编号 | 方向 | 内容 | 状态 |
|---|---|---|---|
| 01 | 前沿全景与跟踪 | 闭源（如 Sora、Veo、可灵、Seedance、Runway）和开源（如 Wan、HunyuanVideo、LTX-Video、CogVideoX）视频生成模型的能力、时长、分辨率、可控性、价格对比；名单以调研时的最新版本为准，定期更新 | 待开始 |
| 02 | 代码驱动的可控生成 | 代码渲染深度 / 边缘 / 分割图和相机轨迹 → 作为控制信号输入视频模型 → 写实画面；对应核心问题 1 | 待开始 |
| 03 | 图生视频补镜头 | AI 生成图片 + 图生视频，补写实镜头，和代码镜头统一色调后混剪 | 待开始 |
| 04 | 视频风格重绘 | 把代码渲染的成片整体重绘成另一种风格（如插画 → 水彩、像素 → 动漫），检验时间上的稳定性 | 待开始 |
| 05 | 角色一致性 | 多镜头里保持同一角色：参考图、角色设定图、局部重绘 | 待开始 |
| 06 | 风格化角色口型驱动 | 非写实（卡通、像素）主持人按配音自动对口型；写实人物不在研究范围内 | 待开始 |
| 07 | 三维重建与运镜 | 高斯泼溅：手机拍一圈实景 → 重建 → 任意运镜 | 待开始 |
| 08 | 音视频联合生成 | 画面和声音一起生成的模型；和 `research/audio/` 分工，结论互相引用 | 待开始 |
| 09 | Agent 化生成 | 大模型规划分镜 → 代码渲染 + 模型补镜头 → 自动审片；结合 `toolkit/vlab/videokit`，参考 Fotor Agent 的思路 | 待开始 |
| 10 | 评测方法 | 怎么客观比较不同方案：可控性、一致性、画质、时长、成本、可复现性、授权 | 待开始 |

**建议顺序**：01（先摸清现状）→ 10（定好评测标准）→ 02、03（和我们路线结合最紧）→ 其余按需。

## 约束

- **算力**：本机显卡是 GTX 1060 6GB。主流开源视频生成模型一般需要更大的显存（以各模型说明为准），
  本地实测前先查要求；多数实验预计走在线接口或租用算力。
- **密钥**：API Key 只放在本地 `.env`（已在 `.gitignore` 里忽略），可以入库一份不含真实值的 `.env.example` 说明需要哪些变量。
- **模型权重不入库**（`.gitignore` 已忽略常见权重格式和 `weights/` 目录），在实验 README 里写清下载方式。
- **费用**：按秒、按次计费的实验，在 README 里记录花费。
- **和项目规则的关系**：`docs/TODO.md` 里"排除大模型方案"约束的是正式视频（`videos/`）的生产路线；
  `research/frontier/` 是研究区，可以试用生成模型。哪项技术进入正式生产，逐项评估后由负责人决定。

---

## 规则

- **一个方向一个目录**：`research/frontier/NN-主题/`，里面放 `README.md`（问题、做法、结论、日期、来源链接）、脚本和 `renders/`（试验输出，入库）。
- **结论必须带日期和来源链接**：这个领域几个月就会变一次，没有日期的结论没有意义。
- **只依赖 `toolkit/vlab/`**，不依赖 `videos/`、`research/visual/`、`research/audio/`。
- 试验输出如果用于对比，同一题材、同一时长、同一分辨率，方便横向比较。

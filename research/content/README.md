# content：创作内容研究

**定位**：`visual/`、`audio/` 研究"怎么做"，这里研究"做什么、给谁看"：
面向大众有哪些内容方向，账号怎么定位，栏目怎么设，稿子怎么写、怎么核实，发布有哪些合规要求。
这里的结论决定接下来补哪些技术和模板。

**面向大众**：选题、语言、时长都按普通观众来定。观众不关心画面是不是代码画的，只关心好不好看、有没有收获。
（制作揭秘副线例外，见 02。）

## 01 大众内容方向（结论）

调研了 20 个方向，原文在 [01-directions/survey-2026-10-21.md](01-directions/survey-2026-10-21.md)，结论在 [01-directions/README.md](01-directions/README.md)。

| 项目负责人点名的方向 | 结论 |
|---|---|
| 面向大众的科普成片 | ✅ 第一主线：需求有数据，和已做的 3 条成片是同一条管线 |
| 音乐配合适的视频 | 🟡 画面是强项，音乐是短板：配乐自己合成；平台曲库只限站内非商业，不能商用 |
| 剪辑影视用的视频做转场 | 🟡 只能当副产品：素材自己是干净的，但规避不了剪辑者的版权问题 |

前 5 个方向：

1. **可视化硬核科普**：数学、物理、天文、气象、计算机
2. **氛围陪伴长视频和自习室直播**：空镜 + 代码合成白噪音，绕开音乐版权
3. **节气与自然现象年度系列**
4. **带讲解的数据和科学模拟短视频**
5. **成片副产品素材库**：空镜、粒子、转场

暂缓：影视剪辑本身、时政资讯、地图和历史疆域、情感语录、儿童绘本、歌词视频、自营 lofi。理由见 01 的总览表。

### 双线策略

- **主线**：面向大众的科普成片，也就是上面的栏目。
  形态待定：调研显示各平台都在扶持横屏中长视频，我们现在只有竖屏短视频管线，见 01 末尾"需要项目负责人定的事"。
- **副线**：制作揭秘，比如"我用代码画出了夕阳为什么是红的"，展示代码、渲染过程和成片对比。
  "用代码画视频"本身是稀缺内容，B 站科技区和开发者圈子有天然受众。
- **互相导流**：副线结尾引到主线成片；主线简介写明画面由代码生成、配音由 AI 合成（AI 标识的要求见 08）。

## 04 选题标准（草案）

每项 0–2 分，满分 14 分，**9 分以上再做**。

| 标准 | 2 分 | 0 分 |
|---|---|---|
| 好奇心 | 一句话就能让人"咦？"（反直觉、常见但说不清） | 大家早就知道，或者根本不关心 |
| 画面优势 | 动画讲比真人讲、比图片讲明显更清楚 | 换成口播也一样 |
| 讲得清 | 核心原理一句话能说清；短视频版 60 秒内讲完，母版也不超过 15 分钟 | 必须铺垫很多前置知识（可以拆成系列） |
| 和生活相关 | 日常现象、常识、正在热议的话题 | 只有专业人士在意 |
| 可核实 | 有教科书、权威机构或论文可查，数字能核对 | 说法众说纷纭、没有可靠来源 |
| 制作成本 | 能用现成模板和画面风格 | 要从零开发新技术 |
| 可系列化 | 能归进某个栏目，还有下一期 | 一次性题目 |

## 05 叙事模板（草案）

| 类型 | 结构 | 例子 |
|---|---|---|
| 科普 | **钩子**（前 3 秒，一个问题或反常识画面）→ **直觉**（大家通常怎么想）→ **反转**（为什么不对）→ **原理**（一步一个画面）→ **升华**（联系生活，留一个问题） | 003 夕阳为什么是红的 |
| 数字快讯 | 数字冲击开场 → 换算成生活里的尺度 → 一个反差 → 结论 | research/visual/12 光有多快 |
| 故事 | **建立**（角色和世界）→ **冲突**（想要什么、遇到什么）→ **解决**（变化、温暖的结尾） | research/visual/11 掉落的星星 |
| 音乐视频 | 按段落切画面：前奏建立氛围，主歌铺陈，副歌换景、加强视觉，节拍点卡转场 | 待做 |

写稿时的硬约束：每句话对应一个画面；画面跟着词走（`timeline.json`）；前 3 秒必须出现钩子，不放片头 Logo。

## 06 文案和核实（草案）

1. **AI 起草**：按 05 的模板写稿，标出每一个事实和数字。
2. **逐条核实**：每个事实找一个可靠来源（教科书、权威机构、论文、官方数据），记录在稿子旁的 `facts.md`：说法、来源链接、查证日期。
3. **数字自己算一遍**：比如"一秒绕地球七圈半"，按 300000 ÷ 40075 ≈ 7.49 验算；"八分多钟"，按日地距离 ÷ 光速 ≈ 499 秒验算。
4. **人工通读**：通读一遍再配音。配音后改稿要重渲染，所以核实必须在配音之前做完。
5. **简化要标明**：为了好懂做了简化的地方（比如光速取 30 万公里/秒），画面上加一行小字注明精确值。

可信度是长期积累的资产，一条错误会抵消很多条正确。

**2026-10-26 起这一节升级为硬性流程**：视频的所有文字都由项目负责人逐条审核、讨论打磨，明确确认后才能配音和渲染，工具会拦。见 `process/SCRIPT-REVIEW.md`。

## 08 合规（要点）

完整清单和来源在 [08-compliance/README.md](08-compliance/README.md)。这不是法律意见。三件最要紧的事：

1. **TTS 配音要标 AI**：发布时勾选平台的 AI 声明，必选标签选「含有AI生成内容」。2025-09 起施行的办法和 2026-05 起的必选标签都要求这样做，剪映等三家已因标识落实不力被查处。视频画面内不加文字声明（项目负责人定，2026-10-23）。
2. **字体**：微软雅黑的著作权归方正，律师称微软无权转授商业发布权，字库公司在批量维权。项目已换成仓库自带的思源黑体（SIL OFL 1.1 可商用，`vlab.fonts`），004 已重渲；001–003 和早期试验还是微软雅黑。
3. **TTS 授权**：Edge TTS 的商用授权不明确，接商单或规模化发布前要换成条款明确的服务。

字体已处理；TTS 授权还没处理，和 audio 06 AI 配音一起做，见 `docs/TODO.md`。

## 规则

- **结论带日期和来源**：平台规则、法规、数据变化很快。写明查证日期和链接；超过半年的结论，用之前重新核实。
- **方向和栏目以数据为准**：试播后按完播率、互动、涨粉调整，不靠感觉。
- **先过合规再动手**：涉及音乐、他人作品、真人形象的选题，先按 08 检查。
- 这里主要是文档；需要脚本时同样只依赖 `toolkit/vlab/`，和其他区不互相引用。

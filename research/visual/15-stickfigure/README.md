# 15 火柴人：火柴人 VS 物理、两个火柴人对打

**日期**：2026-10-27　**状态**：🟡 两段样片完成，等项目负责人看动作质量

## 为什么做

项目负责人问能不能做"火柴人 VS 物理 / 几何"、两个火柴人打架这一类片子（Alan Becker《Animation vs. Math / Physics》那一类）。
这类片子没有旁白，靠动作、音效、音乐撑。粒子、特效和数学物理场景是我们的强项；难点在火柴人的**动作**好不好看。
这两段样片就是拿来判断动作质量的。

**不照搬原作**：角色是我们自己的"光绘火柴人"（每根骨头是一根霓虹管，深色背景、地面倒影），
不用 Alan Becker 的角色形象，也不用《几何冲刺》等游戏的素材。

## 样片

| 样片 | 内容 | 测什么 |
|---|---|---|
| A · 火柴人 VS 物理（6.3 秒） | 助跑一脚把球踢出去，球撞墙、落地、弹回来，被一脚停在脚下 | 关键帧动作（助跑、踢球、停球）；物理可视化：预测抛物线先画出来、每 1/15 秒一个频闪残影、按恢复系数反弹 |
| B · 两个火柴人对打（6.7 秒） | 直拳被后仰躲过 → 上步打肚子 → 跳起侧踢被格挡、滑出去 → 冲刺上勾拳把对方打飞 | 打击感（顿帧、火花、冲击环、震屏、音效）；拳脚按对方关节位置自动够到（IK）；被打飞以后交给布偶物理 |

成片在 `renders/a.mp4`、`renders/b.mp4`（不入库，一条命令重出，见下）。

## 管线

```
Python 算动作（toolkit/vlab/stick/）            Remotion 画（toolkit/.../cards/StickScene.tsx）
  关键帧 + 两段骨 IK（rig.py）   ─┐               光绘火柴人：外晕 + 本色 + 白芯
  Verlet 布偶物理（ragdoll.py）  ─┼→ 每帧 11 个关节坐标 ─→  手脚光迹、冲刺残影、地面倒影和投光
  解析抛体（sample_a.py）        ─┤   + 相机 + 粒子事件     火花 / 尘土 / 冲击环 / 亮斑
  顿帧、相机、震屏（scene.py）   ─┘   + 音效事件 ─────→ vlab.audio.sfx 合成 → mix.mux 混音（-14 LUFS 目标）
```

- **动作时间和真实时间分开**：打中时"顿"几帧（hitstop），动作停住，火花、震屏照常走；写关键帧只管动作时间。
- **物理是真的**：重力 g = 9.8 m/s²，火柴人按 1.75 米换算成像素（1 米 ≈ 190 px）；球的每一段飞行解析求解，布偶用同一个 g。
- **一套骨架**：布偶的质点就是关键帧用的 11 个关节，从关键帧切到物理那一帧不跳；`Figure.ragdoll(until, then)` 留了"倒地后爬起来"的接口（还没用过）。
- 卡 `stickScene` 只吃数据，不认识样片——以后不管动作来自关键帧、物理还是动作捕捉，都走这张卡。

## 跑法

```powershell
uv run python research/visual/15-stickfigure/build.py a            # 样片 A：算动作 → 渲染 → 音效 → 混音 → 抽帧拼图
uv run python research/visual/15-stickfigure/build.py b            # 样片 B
uv run python research/visual/15-stickfigure/build.py b --sheet --at=1.3,1.56,2.48   # 只出骨架拼图（几秒），改关键帧时用
```

一段 6 秒的样片渲染约 1 分钟。`media/` 下是骨架拼图（`*_sheet.png`）、成片抽帧（`*_frames.png`）和无声画面。

## 第一轮的发现

- **能做的**：光绘的质感、打击特效、频闪残影和抛物线这些"算出来的画面"都到位了；布偶被打飞、翻滚、落地很自然，这一段完全是物理算的。
- **还弱的**：
  - 关键帧摆的跑步偏僵（腿太直、没有腾空期），近身对打时两人身体会重叠（两个火柴人之间没有碰撞）。
  - 每秒动作要 5–7 个关键帧，B 这 6 秒写了 40 个左右，还要反复看骨架拼图调。做长片要先攒一个动作库（站架、出拳、踢腿、闪避、挨打、倒地、爬起）。
  - 音效是代码合成的（这次新加了出拳、踢球、格挡、脚步、倒地、撞墙、落地弹起 7 种），比专业音效库单薄；配乐按项目负责人定的，剪辑时从曲库加。
- **下一步可选**：用 MediaPipe 把真人视频（项目负责人自己演）转成关节数据，直接喂给这张卡，对比关键帧版的动作质量；
  或者先攒动作库，再做一条 30 秒左右的完整小故事。
